## 1. 研究定位与核心结论
本项目的核心定位不是“再做一个政策知识图谱”，而是将政策图谱作为**可验证、可交付、可复跑**的数据产品进行方法化构建。其核心价值体现在以下闭环：

1. 语料治理与结构化抽取（Step1-4）  
2. 归一化与机制重绑定（Step5）  
3. 多人双盲一致性与门禁评测（Step6-7）  
4. 图包导出、确定性重放与数据库落地验证（Step8-9）

该闭环将“能看”推进为“能算、能审计、能复现、能迁移”。

## 3. 对标叙事建议（论文可直接采用）

### 3.1 与已有政策图谱工作的差异
已有政策图谱工作多强调“构建流程与可视化分析”。本项目建议明确差异化叙事：

1. 从“构图演示”升级为“可复现评测协议 + 门禁 + 可交付图包”  
2. 从“字段抽取正确性”升级为“可入图可计算性”  
3. 从“单次实验结果”升级为“确定性重放与数据库端到端验收”  

### 3.2 方法论定位
建议将方法定位为“工程化科学方法”而非“单一模型创新”：

1. 抽取层：UIE + 规则后处理协同  
2. 质量层：固定分母 + IAA + 硬错误桶  
3. 交付层：strict_high/strict_all 双轨图包 + manifest/hash  
4. 落地层：Neo4j 导入门禁 + 查询模板验证 + 风险信号覆盖

## 4. 过审短板与最小补强路线

### 4.1 需要补齐的四类证据
1. 外部基线与消融  
2. 泛化（跨时间或跨地区）  
3. 错误画像与成本画像  
4. 复现规范对齐（环境、随机性、可公开边界）

### 4.2 最小改动的三条主线（优先级从高到低）

#### 主线A：可入图评分驱动优化（高优先）
- 目标：证明提升来源于方法贡献，不是口径变化。
- 最小产出：
  1. 一张主表：`iter0 -> iter3` 指标分解；
  2. 一张分解图：`structure/evidence/doc/clause` 对总分贡献；
  3. 一段消融：关闭规则后处理或关闭重绑定，比较 `strict_triplet_ready_rate` 与 `param_bind_rate`。

#### 主线B：评测协议化（高优先）
- 目标：把门禁“日志化结果”升级为“可复写协议”。
- 最小产出：
  1. 分母定义与冻结规则；
  2. 双盲抽样与仲裁规则；
  3. 硬错误桶定义与通过条件；
  4. 所有门禁阈值显式公开。

#### 主线C：图包交付与数据库闭环（高优先）
- 目标：突出工程可落地和可审计可迁移。
- 最小产出：
  1. Supplement 目录给出交付包结构；
  2. 用 `manifest+sha256` 定义结果身份；
  3. 用 Step8.2/Step9 报告证明“可运行闭环”。

## 5. 论文写作中的“定义级”增强点

### 5.1 证据坐标协议（必须定义）
建议在方法节以正式定义写清：

1. offset 基于 decoded text 的 character index  
2. span 区间采用 `[start, end)`  
3. `evidence_scope=clause` 时，offset 相对 `clause_text`  
4. 关键字段包含 `evidence_span_start`、`evidence_span_end`、`evidence_text_sha256`

这将“可追溯”从工程实现提升为论文可检验定义。

### 5.2 双轨图包使用协议（必须定义）
建议明确 `strict_high` 与 `strict_all` 的契约：

1. `strict_high`：正式统计、推演与结论主图  
2. `strict_all`：候选发现与人工复核图  
3. 两轨共享 schema、证据协议与重放验证机制

### 5.3 Neo4j 可迁移导入规范（建议补充）
建议在系统实现节显式写出：

1. 导入顺序（节点后关系）  
2. 约束与索引策略（唯一键、常查字段）  
3. 导入后门禁检查项（node/edge/traceability/query coverage）
